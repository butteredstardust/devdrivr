# Security Policy for devdrivr

## Report a security vulnerability

Report vulnerabilities privately through [GitHub's private vulnerability reporting](https://github.com/butteredstardust/devdrivr/security/advisories/new). Use the repository [Security tab](https://github.com/butteredstardust/devdrivr/security).

Include steps to reproduce the issue, affected versions, and other details that help the investigation.

### Scope

This policy applies to versions hosted in the official [butteredstardust/devdrivr](https://github.com/butteredstardust/devdrivr) repository on GitHub.

### Response time

We aim to acknowledge a vulnerability report within 10 business days. We provide an estimated resolution timeline.

### Disclosure

We validate each report. We develop and release a fix before public disclosure.

We coordinate disclosure with the reporter to protect devdrivr users.

### Fix process

We prioritize reports by severity and impact. We develop and validate fixes as soon as possible.

The patch timeline can vary with complexity and contributor availability.

### Acknowledgment

We acknowledge responsible reporters unless they request anonymity. State your credit preference in the report.

### Good security practice

- Update to the latest stable release for security fixes and improvements.
- Do not use code from untrusted or insecure sources.
- Use input validation, output encoding, and error handling.
- Report vulnerabilities through this policy.

This policy can change without notice. Check the latest version in the official repository.
